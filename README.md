# Kijk

Host private HTML on a public GitHub Pages site. Your repo stores only an encrypted payload and a small decryption wrapper — visitors need the password to see anything.

## How It Works

1. You write your secret HTML locally
2. A script encrypts it with AES-256-GCM (PBKDF2-derived key, 600k iterations)
3. The encrypted blob is committed to the repo
4. GitHub Actions builds a single `index.html` that contains a password prompt and the decryption logic
5. Visitors enter the password, the browser decrypts and renders the content — no server needed

The deployed page shows a password dialog with your custom title. After unlocking, the decrypted content replaces the page. A logout button lets you clear the session.

Sessions persist within a browser tab via `sessionStorage` (derived key bits, not the password). Closing the tab clears the session automatically.

## Quick Start

### Prerequisites

- Node.js 20+
- A GitHub repo with Pages enabled (deploy from `gh-pages` branch)
- A fine-grained GitHub PAT (only needed for the access monitoring feature)

### 1. Clone and install

```sh
git clone <your-fork-url>
cd kijk
npm install
```

### 2. Add your secret content

Create two files in `secrets/` (this directory is gitignored):

**`secrets/page.html`** — the HTML you want to protect. This can be a full HTML document or a fragment.

**`secrets/info.json`** — your configuration:

```json
{
  "master-key": "your-strong-password",
  "pat": "github_pat_xxx",
  "title": "My Secret Page"
}
```

| Key              | Required | Description                                           |
| ---------------- | -------- | ----------------------------------------------------- |
| `master-key`     | Yes      | Password used to encrypt and decrypt the content      |
| `pat`            | Yes      | GitHub fine-grained PAT for access monitoring         |
| `title`          | No       | Heading shown on the password dialog (default: "Kijk") |
| `pat-key`        | Auto     | AES key for monitoring encryption (generated by `prepare.sh`) |
| `monitor-issue`  | Auto     | GitHub issue number for the access log (generated by `prepare.sh`) |

### 3. Create a GitHub PAT

This is needed for the access monitoring feature.

1. Go to **GitHub > Settings > Developer settings > Fine-grained personal access tokens**
2. Create a token scoped to **this repo only**
3. Grant permission: **Issues — Read and Write**
4. Copy the token into `secrets/info.json` as `pat`

### 4. Prepare and deploy

```sh
./prepare.sh
```

This script:
- Encrypts `secrets/page.html` with your master-key
- Auto-generates a `pat-key` for monitoring encryption (saved back to `info.json`)
- Finds or creates an "Access Log" issue on your repo
- Writes all artifacts to `encrypted/`

Then commit and push:

```sh
git add encrypted/
git commit -m "Update encrypted content"
git push
```

The included GitHub Actions workflow builds the final page and deploys it to `gh-pages` automatically.

### 5. Preview locally

```sh
npm run build
```

Then open `dist/index.html` in a browser.

## Updating Content

Whenever you change `secrets/page.html` or `secrets/info.json`:

```sh
./prepare.sh
git add encrypted/
git commit -m "Update encrypted content"
git push
```

## Access Monitoring

Every page visit is logged as an encrypted comment on a GitHub Issue in your repo. This gives you an access log without any server infrastructure.

### What gets logged

- **Unlock** — successful password entry (date, IP, user agent)
- **Session restore** — returning visitor with a valid session
- **Failed attempt** — wrong password entered

### Encryption tiers

Log entries use two encryption tiers so the issue comments are unreadable to casual observers:

- **Secure** entries are encrypted with the content-derived AES key. Only someone who knows the password can read them.
- **Obfuscated** entries (failed attempts) are encrypted with the pat-key. You can read these with the monitor script.

### Reading the log

```sh
npm run monitor
```

This decrypts all comments and prints an aligned table:

```
TIER    EVENT            DATE                 IP             UA
──────  ───────────────  ───────────────────  ─────────────  ──────────
SECURE  Unlock           2025-01-15 14:23:01  203.0.113.42   Mozilla/5.0 ...
OBFUSC  Failed attempt   2025-01-15 14:22:55  203.0.113.42   Mozilla/5.0 ...
```

It also writes a markdown report to `secrets/monitor.md`.

## Project Structure

```
secrets/                    # gitignored — your private files
  page.html                 # the HTML to encrypt
  info.json                 # master-key, pat, pat-key, title, monitor-issue
  monitor.md                # generated access log report

encrypted/                  # committed — safe to publish
  payload.enc               # AES-256-GCM encrypted content (base64)
  monitor.enc               # encrypted API URL + PAT for monitoring
  monitor.key               # AES key for obfuscated log entries
  title.txt                 # page title for the password dialog

src/
  wrapper.html              # password form + Web Crypto decryption logic
  encrypt.mjs               # encrypts page.html → payload.enc
  build.mjs                 # assembles wrapper + payload → dist/index.html
  monitor.mjs               # CLI to fetch and decrypt access log

dist/                       # gitignored — build output
  index.html                # the deployable page

prepare.sh                  # one-command setup: encrypt everything
.github/workflows/deploy.yml  # CI: build + deploy to gh-pages
```

## npm Scripts

| Command                  | Description                                      |
| ------------------------ | ------------------------------------------------ |
| `npm run build`           | Build `dist/index.html` from wrapper + payload |
| `npm run monitor`         | Fetch and decrypt the access log               |
| `npm run prepare-secrets` | Run `prepare.sh`                               |

## Encryption Details

- **Algorithm:** AES-256-GCM
- **Key derivation:** PBKDF2 with SHA-256, 600,000 iterations
- **Payload format:** base64 of `salt(16) || iv(12) || ciphertext || authTag(16)`
- **Encryption:** Node.js `crypto` module
- **Decryption:** Web Crypto API (runs entirely in the browser)

## Security Notes

- The encrypted payload is safe to commit publicly — it cannot be decrypted without the password
- The `pat-key` and `monitor.enc` are committed, but the PAT is encrypted inside `monitor.enc`
- The password is never stored — only the derived AES key bits are kept in `sessionStorage` for tab-scoped session persistence
- `secrets/` is gitignored and should never be committed
- The `prepare.sh` script auto-generates cryptographic keys; you do not need to create them manually
